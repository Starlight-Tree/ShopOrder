# docs/ を触るとき

どの文書が何の正本かは [docs/CLAUDE.md](../../docs/CLAUDE.md)。

- 確認していないことを「確認済み」と書かない。状態は「報告（人・資料の申告）/ ソースで確認 / 未確認」の別を書き、推測は推測と書く
- 数字と状態には、日付と測り方を添える
- 同じ事実を複数の文書に書かない。世界観（店・地名・通貨ルミ・メニュー・価格）は [docs/world.md](../../docs/world.md) が正本で、他からはリンクで指す。設定の区分は「資料」「決定」「新設」。新設の設定を、資料の事実として書かない
- 決定は `docs/decisions/` に 1 件 1 ファイルで書く（状態・日付と決めた人・背景・決定・結果と限界・出典）。決定済みの ADR は書き換えず、新しい ADR で置き換える
- 文書やファイルを移す・改名するときは、リンク・バッククォートのパス・節名・コードのコメントの参照を `git grep` で洗い、全部直す
- 秘密（キー・トークン・接続文字列）は書かない。登録語（`.git/sensitive-terms`）に当たるものは書かない。確認は `scripts/check-sensitive-terms.sh`
- 「最新の流行」「業界標準」のような主張は、出どころ（一般知識か、今回の調査か。調査なら公式の URL）を 1 行で書く
- 直したあと、別の目（`docs-reviewer`）で確かめてよい。指摘は、再現できたものだけを取る
