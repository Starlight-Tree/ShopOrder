# 引き継ぎ（読み取りと報告が中心。消す・押すは、承認を得てから）

次のセッションが、会話の履歴なしで続けられる状態にする。

1. **状態を確認する（読み取りだけ）。**
   - `git status -sb`、`git log --oneline origin/main..HEAD`（未プッシュのコミット。最後に fetch した時点の `origin/main` との差）、未コミットの差分（頼まれない限り触らない・コミットに含めない）
   - 動いているバックグラウンドの作業（Workflow・起動したサーバー）と、承認待ちの操作（プッシュなど）
   - `docs/world.md` の「新設」の未決の項目と、`docs/decisions/` の状態が「提案」の ADR が、今の作業で変わったか
2. **消えうる物を退避する。** 作業用の一時ファイル（スクラッチパッドなど）で、次に要るものは、退避する対象と写し先を示してから写す。コンテナでは、リポジトリの `.dev-local/`（Git の管理外）へ。ホストの作業なら `~/Backups/<対象>/`（対象ごとに最新の 1 つ、日付なしの名前で上書き。共通ルール）。コンテナからは `~/Backups/` に書けない。**秘密を含むものは写さない。**
3. **引き継ぎの要点を整理する。** 次の 5 点を、短く。
   - 完了したこと（何を実行・確認したか。確認していないことは「未確認」）
   - 承認待ちのこと（プッシュ・デプロイ・実 API。件数・回数・概算費用が要るもの）
   - 未コミットの差分と、その理由
   - 未解決の問い（決定が要るもの）
   - 次の一手 1 つ
4. **後始末をする。** 自分が起動したサーバー・スクリプトだけを、PID を指定して止める。他のものは止めない。消す前に、対象と参照を示して承認を得る。

守ること: プッシュ・デプロイ・`git reset` / `git restore` は、この手順の中でも、操作ごとに承認を得る。`.env` と `backups/` は読まない。値を出さない。
