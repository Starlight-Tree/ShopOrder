# 0003 AI は注文を確定せず、確定は画面の確定ボタンだけにする

- 状態: 決定（2026-11-21 にユーザーが承認。異議があれば新しい ADR で置き換える）
- 日付と決めた人: 2026-11-21（私の提案をユーザーが承認）

## 背景
ユーザーの規約: AI は、注文の確定・決済・個人情報の変更を、人の確認なしにしない。DocuNavi のチャットは読み取りだけで、書き込みと人の確認の仕組みが無い。
## 決定
- AI に渡すのは「カートの下書き」と「確認カード（`propose_checkout`）」まで。`place_order`・決済・返金・住所や電話の変更のツールは渡さない。
- 確定は REST。`checkout_proposal`（カートの版・合計・期限に結び付く）が有効で、`sub` がカートの持ち主で、価格・在庫・営業時間を再検証し、冪等キーがあるときだけ通る。
- 確定ボタンは、サーバーが返す確認カードにだけ出す。LLM の文章からは出さない。
- グラフを途中で止めて再開する方式にはしない。
## 結果と限界
- 被害の上限を、ツールの設計で決められる。「注文しました」という LLM の文面は事実として扱わず、出力ガードで置き換える（未実装・P3）。
- 間接プロンプトインジェクション（商品名・備考・メッセージ）は、ツール結果を信頼できないデータとして包むことで減らすが、ゼロにはならない。評価の赤チームで見る（P3）。
