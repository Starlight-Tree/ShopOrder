# 0004 在庫は台帳 + 残高で持ち、確保は注文の確定時に条件付き UPDATE で行う

- 状態: 決定（2026-11-21 にユーザーが承認。異議があれば新しい ADR で置き換える）
- 日付と決めた人: 2026-11-21（私の提案をユーザーが承認）

## 背景
二重売り・二重引当てを防ぎ、棚卸しの差異と原価を追えるようにしたい。Square・Shopify の在庫 API は、数量を状態間の移動（調整）として持ち、実数の確認が計算値を上書きする（調査: 公式文書、2026-11-21）。
## 決定
- `stock_movements`（追記のみ）を正本、`stock_balances`（on_hand・reserved）を同じトランザクションで更新し、夜間に台帳から再計算して照合する。棚卸しは差異を `adjust` の行として足す。
- 確保は「カートに入れた時」ではなく「注文の確定の時」。`UPDATE ... SET reserved = reserved + :n WHERE on_hand - reserved - safety_stock >= :n` の 1 文（READ COMMITTED の再評価で二重売りを防ぐ）。`CHECK (on_hand >= 0 AND reserved <= on_hand)` が最後の砦。
- 支払いまでの期限は既定 15 分。worker が戻し、アクセス時にも遅延で戻す。
- ロットは賞味期限のあるもの（豆・菓子・牛乳）だけ。引当ては FEFO。ロックは品目 → 期限 → lot_id の固定順。原価はロット別の仕入単価。
- 在庫は原材料（生豆・牛乳・カップ）と販売品目（豆の袋・菓子）の二層。ドリンクは調理開始でレシピの原材料を消費する。
## 結果と限界
- 未確認: 実際の同時実行での挙動（P1 で並行リクエストのテストを書く）。レシピの使用量はダミー。
- 見送り: 「取り置き・入荷待ち予約」。在庫切れは売り切れ表示だけ。
