# 0005 決済・配達・通知・LLM は模擬を既定にし、差し替え口を残す

- 状態: 提案（ユーザーの「お任せ」で進める。異議があれば新しい ADR で置き換える）
- 日付と決めた人: 2026-11-21（私の提案。ユーザーは「どんどんお任せで進めてていい」と委任）

## 背景
実 API・課金・外部への書き込みは承認制（ユーザーの規約）。架空の世界なので、実在の決済・地図・メールは使えない（使う必要もない）。JobNavi の `Storage`（Protocol + 2 実装 + 設定で選ぶ + 偽物でテスト）が型になる。
## 決定
- `PaymentProvider`・`DeliveryProvider`・`Notifier`・`ChatModel` を Protocol にし、既定は模擬。設定の値が不正なら起動失敗（別の実装へ黙って落とさない）。
- 模擬は、時間経過で状態が進む（worker）。テストは偽物を差す。
- 実 API（Gemini）は無料キー・ローカルのみ・承認制。本物の決済・メールは P6（実際に使うとき）で、ユーザーの承認を得てから。
- 冪等キーを注文の確定・決済・状態変更に必須にする。
## 結果と限界
- 実在の事業者の API の形（webhook・署名）は、模擬では確かめられない。差し替えのときに作り直す部分が出る（未確認）。
