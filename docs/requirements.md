# 要件

オアシス珈琲（惑星ザーハード、アルカ市の 12 店舗）の、**商品の注文と宅配のアプリ**。世界観・店・通貨の正本は [world.md](world.md)。ここにある設定のうち、資料に無いものは「新設」（world.md の区分）。

依頼（2026-11-21、ユーザー）: ①画面で注文できる ②チャットで注文の手配ができ、配達まで通る ③売上分析・在庫管理・グラフ・顧客データの分析 ④既存プロジェクト（JobNavi・DocuNavi）の流儀で作る。細部は「お任せ」。

## 誰が使うか

| ロール | 何をする | ログイン |
|---|---|---|
| 顧客 | メニューを見て注文（画面・チャット）、受け取り方法（店頭 / 宅配）を選ぶ、状況を見る、履歴・ポイント | Google（JobNavi の求職者と同じ。開発中は模擬ログイン） |
| 店舗スタッフ | 自店の注文を受ける・調理する・渡す、在庫を数える・入荷する、配達員を割り当てる | 店のアカウント（パスワード。JobNavi の園と同じ別系統） |
| 配達員 | 割り当てられた配達を受ける、集荷・配達・不在を記録する | 同上（role = courier） |
| 店長 | 自店 / 全店の売上・在庫・顧客の分析を見る、メニューと価格・配達区画と送料・営業日を決める | 同上（role = manager） |

顧客とスタッフは、アカウントもセッションも Cookie も別（JobNavi と同じ）。

## 範囲

**MVP（最初に動くもの）**
1. メニュー（ドリンク・フード・豆）を見て、カートに入れ、店と受け取り方法を選び、**模擬決済**で注文できる（画面）。
2. 注文は状態機械で進む（受付 → 調理 → 準備完了 → 渡す／配達 → 完了）。スタッフの画面（調理ボード・配達ボード）で進める。
3. 宅配: 配達区画・時間枠・送料・配達員の割り当て・暗証コードでの受け渡し・不在。
4. 在庫: 入荷・消費（レシピ）・廃棄・棚卸し・発注点の警告。注文確定で在庫を確保する。
5. チャットで注文: AI 店員と話して商品を選び、カートを作る。**確定は画面の確定ボタンだけ**（[chat.md](chat.md)）。
6. 分析: 売上・商品・時間帯・在庫・配達時間・顧客（RFM・再購入）のグラフと表（[analytics.md](analytics.md)）。

**後で（設計は入れておく）**: 注文ごとの連絡スレッド（顧客・店・配達員）、Web Push、実決済、実在の地図、巡回の最適化、予約注文・定期購入。

**やらない**: 実在の決済・実メール・実在の位置情報への接続（差し替え口は残す）、機械学習の予測。

## 守ること（ユーザーの規約と、その具体化）

- **AI は、注文の確定・決済・個人情報の変更を、人の確認なしにしない。** 確定のツールを AI に渡さない（[chat.md](chat.md)）。
- **権限は API が毎回確認する。** 他人の注文・他店のデータは、存在しないのと同じ 404。顧客・店・配達員・店長で見える項目も違う。
- **実 API・課金は承認制。** 開発の既定は、模擬の決済・配達・通知・LLM。本物への差し替えは設定で選び、既定にしない。
- 秘密は環境変数。コード・文書・ログに値を書かない。`.env` は読まない。
- 世界観は world.md を正とし、資料に無い設定は「新設」と明記する。通貨はルミ（整数）。

## 非機能

- 画面は日本語。ライト・ダーク。幅 1280px 基準、390px で横スクロールが出ない。WCAG AA の色、グラフは「表で見る」を持つ。
- 金額・在庫の数は整数。二重注文・二重売り・二重引当てを、冪等キーと DB の制約で防ぐ。
- ローカルの Docker Compose だけで動く（外部サービス無し）。ポートは画面 3400・API 8400（JobNavi の 3200/8200、DocuNavi の 3000 と同時に動かすため。変えない）。
- 個人情報（住所・電話・注文履歴）は最小限にし、ログに出さない。分析には仮名 ID だけを渡す。
